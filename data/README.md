# 数据目录

| 目录 | 放置内容 | Git 管理方式 |
| --- | --- | --- |
| `raw/` | 原始旅行资料、网页导出、PDF 等 | 默认仅保存在本地 |
| `processed/` | 清洗、结构化或切分后的数据 | 默认仅保存在本地 |
| `indexes/` | 向量索引或其他检索生成文件 | 默认仅保存在本地 |

这些目录已配置忽略规则，仅保留 `.gitkeep`。资料更新后，应通过明确的共享来源同步，或使用脚本重新生成处理结果和索引。

团队确定资料后，在下方补充来源清单，方便组员获得同一份数据：

| 资料名称 | 来源链接或共享位置 | 获取日期/版本 | 本地保存路径 |
| --- | --- | --- | --- |
| 待补充 | 待补充 | 待补充 | `data/raw/` |

如需提交少量可公开的演示数据，先明确文件、用途与大小，再单独调整对应的忽略规则。

## 当前可运行资料

根目录 `data/places.json` 保存 33 条附官方来源的地点摘要，`transit.json` 保存本地整理的线路与出口参考。`eval_cases.json` 为开发例题，`holdout_cases.json` 为冻结检查题；这些小型公开演示文件已提交。索引与本机历史写入忽略目录，不提交数据库。

原始来源、核对日期及坐标假设见每条记录与 [`docs/数据说明.md`](../docs/数据说明.md)。候选资料先通过 `scripts/manage_data.py` 校验，不能直接覆盖冻结检查题或据其调参。

## 六模块数据设计（2026-10-24，已实现 Demo）

- [数据准备清单](DATA_INVENTORY.md)：需要收集的数据、来源台账、目录和质量要求。
- [字段与类型字典](DATA_DICTIONARY.md)：知识数据、实体关系、用户会话、长期记忆、索引与评测格式。
- [空白采集模板](templates/)：七份 CSV 表头和一份明确标记虚构的评测格式示例，尚无真实采集数据。
- [整体架构与 Docker 计划](../Doc/README.md)：六模块全部纳入范围，三容器部署设计。

`templates/` 中只有字段定义和格式示例，可提交 Git；原始资料和生成物继续遵循上述本地保存规则。后续新增评测集/报告目录前，需确定公开样本和运行产物的忽略规则。

## 已实现的数据工具

随附 [虚构演示资料](demo/README.md) 可用 `bootstrap --demo` 初始化。真实 CSV/JSON 的导入、校验、索引和评测步骤见 [运行指南](../Doc/04-run-and-env.md)。模拟数据与真实质量评测必须分开。

两套资料不会自动互相导入：根目录应用读取 `places.json` / `transit.json`；Docker 六模块应用从 `demo/bundle.json` 或经校验的 CSV/JSON 导入数据库和索引。
