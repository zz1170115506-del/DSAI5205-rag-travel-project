# DeepSeek 本地接入（2026-10-20）

本机配置在项目根目录 `.env`，权限为 0600，并由 Git 忽略；源码、证据和浏览器均不包含密钥。使用官方 HTTPS 地址 `https://api.deepseek.com/v1` 和 `deepseek-flash`，采用非思考模式，以便演示低延迟的工具调用。模型和请求字段核对自 [官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)，并实际访问 `/models` 验证认证与可用模型。

运行 `python run.py --port 8767` 后，在“问一问”勾选“使用大模型回答”，或者在“接着聊”勾选“让模型选择工具”。默认不开启外部请求。前者发送问题与检索片段；后者还发送有限会话历史、条件和工具结果。切换模式前需要清除旧会话。费用由供应商实际用量决定，项目没有准确计费器，`cost: null` 表示未知。

真实运行检查包括：认证 HTTP 200；“大馆有什么文化特色？”的模型问答及 `tai-kwun` 引用；浏览器中模型连续调用本地 `search_places`、`place_detail`，再生成通过当前校验的回答。浏览器这轮记录为 3 次真实模型响应、2 次成功 stdio MCP 调用，总耗时 4496 ms。这是单次开发运行观察，不代表平均速度、准确率或稳定性。

首次工具循环完成后，模型额外写出“开放时间与预约要求需另查”的提醒，命中现有保守关键词保护，系统回退本地摘录。随后补充模型提示：非动态问题仅介绍静态特色，不额外讨论动态话题。保留原有动态问题拦截及成文校验。修改后浏览器运行正常；该调整不证明所有表述都能通过，也没有用冻结保留集调参。

执行记录中的 `model_calls` 是尝试次数，`model_responses` 是收到并解析的成功 HTTP 响应数，`live_model_responses` 排除显式注入的 HTTP 测试传输。`external_model_verified` 仅表示本轮确实收到外部模型响应；`answer.model_output_accepted` 表示最终文字通过当前格式与引用校验。两者都不是事实正确率。守卫提前终止的下一轮不会继承上一轮的响应计数。

本次回归：135 项 Python 检查、5 项前端缓存检查、22/22 开发检索例题，资料校验、只读本机诊断和 4 组真实 stdio 开发验收均通过。回归脚本不调用真实模型；其中模型分支使用模拟 HTTP 响应，与另行运行的真实接通检查分开记录。

机器可读记录见 `docs/evidence/deepseek-2026-10-20/`。高德、手机、Windows、生产部署及大规模模型质量评测均未在本次验证。没有访问 Canvas，也没有推送 GitHub。
