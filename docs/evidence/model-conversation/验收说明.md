## 最终行为

开启“使用大模型”后，模型读取近期消息、当前旅行条件、上轮展示地点、最新逐日行程和偏好备注，自行理解指代、否定、修改及回顾请求。模型模式不调用 `extract_patch` 或 `resolve_reference` 关键词解释器；测试将这两个函数替换为报错函数，仍完成连续修改。本地演示保留规则路径，页面清楚显示模式及数据发送范围。

模型可调用原有检索、详情、交通及规划工具，另增加三项有边界的工具：

- `update_trip`：只修改明确提出的字段；规范化日期、兴趣枚举、地点与出发站，最多记 8 条简短备注。排除地点在后续重排时仍排除。
- `revise_itinerary`：删除、替换、移动、添加地点或交换两天。保留其他日程，重新估算停留、交通、首站接驳与结束时间；检查日期、重复地点、必去／仅选／排除条件、每日容量和区域／室内约束。
- `read_itinerary`：读取已保存的行程与偏好，用于回答“第二天去哪”“和谁同行”“不去哪里”等回顾问题，不修改状态。

工具状态改变由服务端校验后原子返回，不能执行任意代码或文件操作。引用仍限定于规范资料；已选和已排除地点也作为合法回顾来源，避免“我不去哪里”被当作无依据的地点推荐回退。模型可以发出澄清问题，缺少引用的澄清不会被固定推荐覆盖，也不会送去高德搜索。

上下文上限为 24 条消息、24,000 字符；每条消息最多 4,000 字符。另保存最新行程的规范地点编号、完整日历长度及最多 8 条、每条 160 字的偏好备注。SQLite 保留最近 20 轮，重新打开历史时重建有界上下文；更早文本不保证仍在模型窗口。当前结构化条件优先于旧备注。备注未必有对应算法约束，不能据此承诺酒店往返、无障碍或完整预算。

每条历史增加铅笔重命名，1–60 字，取消不保存。SQLite 新增手动名称标记，读取时覆盖旧 payload 标题；继续聊天即使拿到旧标题，也通过 UPSERT 保留手动名称。重命名不改变聊天时间、收藏和置顶。四个操作在同一行展示，长标题截断并保留完整提示；已修正列表横向溢出。

## 真实 DeepSeek 合成联调

最终证据为 `live-smoke-verified.json`，六轮均完成，模型回答均通过格式和引用校验，全部包含真实模型响应。使用独立 `work/qa-model-conversation/`，没有读取或发送用户实际历史，没有高德调用。

| 轮次 | 请求 | 结果 |
| --- | --- | --- |
| 1 | 与父母看海，先推荐两处 | 星光大道、西九艺术公园 |
| 2 | “那就刚才这两处”，10 月 24–25 日，只去它们 | 每天一处，保留日期与仅选条件 |
| 3 | 第一天休息，两处都挪到第二天 | 第一天空余，第二天两处，重算交通 |

| 5 | 交换前两天，其他不动 | 从 SQLite 恢复后交换，24 日两处、25 日休息 |
| 6 | 还记得与谁同行、不想去哪吗 | 正确回顾父母同行、排除西九、当前两处及日期 |

这六轮由同一合成历史分段恢复完成，**不是一次无中断运行**。前期记录保留在其他 `live-smoke*.json`：曾遇到非法兴趣值、供应商工具调用后返回纯文本，以及一次连接失败。最终增加兴趣枚举、可恢复状态、一次无工具 JSON 格式修复和连接重试。格式修复请求计入 `model_calls`、实际响应计入 `model_responses`，不会再次执行行程修改。最终证据中的部分轮次包含一次格式修复。少量真实联调不代表任意自然语言成功率或生产可靠性。

JSON 输出配置参考 [DeepSeek 官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。即使启用了 JSON 模式，仍对实际响应执行边界和引用校验；修复失败则明确停止，不伪装成正常回答。
