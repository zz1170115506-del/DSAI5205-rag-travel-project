# 连续地点指代与精确选择修复

日期：2026-10-22。本地开发修复，Codex 辅助完成；未推送公开仓库。

用户问题：上一轮推荐星光大道、西九艺术公园后，“那我就去这两个地方”误入高德地点补充。原因是会话仅保存文本及旅行条件，未记录已展示的地点；规划中的必去条件也仅为优先项，不能表达“只去这两处”。

## 当前行为

- `place_context` 保存规范地点 ID 的展示列表与焦点，最多 30 条。序号按回答文字中的引用顺序，未展示的候选不参与指代。
- “那我就去这两个地方”将选择写入旅行条件，并开启 `only_selected`；沿用日期、地区、节奏等约束。仅在既有 3 个必去地点上限内规划。
- “第二个有什么特色”“那第一个呢”保留原列表顺序；“这两个地方之间怎么走”调用本地交通工具。
- 缺少日期时先记下选择再询问；数量不符、没有上下文或排除意图不明确时先澄清，不查询地图。
- 仅选地点不自动补餐馆或其他景点；天数较多时完整保留日历，空余日明确标为按选择保留的休息／自由活动。
- SQLite 保存结构化上下文。旧历史从已有引用／行程恢复；之前误将指代句查询地图的失败轮次会被跳过。不会重写原历史答案。
- 新话题更换列表；不同对话不会互相继承地点。外部未审核地图地点尚不支持加入本地精确选择规划。

## 验证

`regression/summary.json`：全部 6 组通过；`python-tests.txt` 为 242 项通过，`frontend-tests.txt` 为 12 项通过。`local-doctor.txt` 实际启动本地 stdio 子进程，完成 initialize → tools/list → tools/call。检索开发例题与这些测试不代表独立自然语言理解准确率。

新增 24 项检查覆盖用户原句及常见变体、序号与展示顺序、两地交通、无上下文澄清、先选后补日期、新话题、旧失败历史恢复、数量歧义、精确地点规划、只选餐饮、日期完整、条件冲突和会话隔离。测试将地图函数设为禁止调用，指代场景若触发外部查询即失败。

浏览器在独立 8768 站点和临时 SQLite 历史库验证，模型与高德均关闭，使用真实本地 MCP：

1. 选择 2026-10-22 至 23 日，发送“我想去海边玩”；页面列出星光大道、西九艺术公园。
2. 发送“那我就去这两个地方”；确认两个名称、保留日期、侧栏勾选“只安排已选地点”，每日各安排一处，没有额外停留点。
3. 刷新后发送“第二个有什么特色”；正确回答西九艺术公园。
4. 发送“这两个地方之间怎么走”；给出尖东站 → 屯马线 → 柯士甸站 D1 出口的本地参考，未进入地图地点补充。
5. 重启测试服务、刷新页面后问“那第一个呢”；正确回答星光大道。
6. 重启用户 8767 服务，确认页面加载 `/static/app.js?v=1.3.12` 和新侧栏选项；刷新前已确认提问草稿为空。
