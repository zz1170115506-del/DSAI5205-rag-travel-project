# 港慢游 1.3：统一旅行对话与 TravelTrace 参考设计

修改对象是 `hk-travel-assistant`，不是 TravelTrace。用户提供的 `TravelTrace-frontend-local.zip` 只作设计参考，解压副本位于被 Git 忽略的 `work/traveltrace-reference/`；原压缩包未改动。港慢游沿用自己的 FastAPI、DeepSeek、LangGraph 和真实本地 MCP 工具。

## 页面与使用

首页采用参考中的深绿/浅绿配色、大幅横幅、悬浮规划栏与三张主题卡。品牌仍为港慢游。照片继续引用附件内的 Unsplash 图片 URL；无外部图片时以本地 `harbour.svg` 为背景后备，不加载外部字体。照片仅作旅行灵感装饰，不构成具体地点的证据。

导航保留“探索香港”“问一问 · 排行程”“地点资料”和运行状态。“接着聊”和独立规划页已合入“问一问”：同一段对话可提问、从侧栏选择偏好排行程、继续修改条件、查看来源、下载对应轮次的行程与展开实际工具记录。首页规划也进入同一入口。原 `/api/ask`、`/api/plan`、`/api/agent` 接口继续兼容，网页改用 `/api/chat`。

## 资料库与检索

本地资料由 21 条扩充至 **33 条**，新增 12 条：香港公园、香港动植物公园、九龙公园、维多利亚公园、蓝屋建筑群、湾仔北帝庙、香港科学馆、香港太空馆、尖沙咀钟楼、金鱼街、旺角花墟、女人街。新增记录按 2026-10-22 核对的香港旅发局页面概述，逐条保留链接及日期；原 21 条保留原核对日期。湾仔、铜锣湾另设规划街区，避免将它们全部塞进中环路线。

活动资料仍以经过 Pydantic 校验的 `data/places.json` 为规范来源；运行时建立 SQLite FTS5 全文索引。检索分两步：BM25 召回最多 24 个候选，再按名称/别名命中、文本词覆盖、街区和主题特征重排。结果含召回分数、重排特征与候选数。**这是词法检索与可解释特征重排，不是向量数据库、神经重排或已证明的准确率提升。** 不运行付费重排 API。旧 `knowledge.search` 保留为历史基线；真实 MCP `search_places` 和当前地点搜索使用新流程。

冻结保留集未改动，也没有据其结果调参。坐标、停留时长、费用类别仍为本项目人工规划假设，不能解释为官方测量或实时票务。

## 本机历史

新增 SQLite 文件 `work/user-data/conversations.sqlite3`，文件权限 0600、Git 忽略。每段保留最近 20 轮，最多 25 段；达到容量后提示删除旧对话，不自动清除。历史同时保存规范偏好与有限上下文检查点，服务重启后重新创建 Agent 并恢复状态。新对话不会删除旧历史，删除按钮只删除对应本机记录。浏览器仅保存当前历史 ID；数据库包含明文旅行对话，不是云同步或多用户账户系统。

接口：`GET /api/history`、`POST /api/history/read`、`POST /api/history/delete`。ID 严格校验，SQL 参数绑定，写入事务与每段对话锁防止并发覆盖；不保存旧运行会话 token。已知配置密钥会从问答与归档中替换为 `[redacted]`。同源限制继续生效，API 与页面不缓存，静态资源使用版本号与重新验证，避免旧 JavaScript 对上新 HTML。

## 小众地点 JSON 接口

`POST /api/places/resolve`

```json
{"query":"具体香港地点名称"}
```

先查本地名称/别名；命中后不请求高德。未命中才尝试高德 `GET /v3/place/text`，限制香港城市、最多 5 条，再核对返回地区及坐标范围。主要返回字段：

```json
{
  "mode":"live | local | empty | not_configured | unavailable",
  "provider":"amap | curated_local",
  "external_requested":false,
  "results":[{
    "id":"amap-供应商编号",
    "name":"地点名称",
    "address":"地图返回地址",
    "location":[114.17,22.3],
    "coordinate_system":"GCJ-02 (provider supplied)",
    "source":{"name":"高德地图 POI 搜索","url":"官方接口说明","fetched_at":"请求时间"},
    "review_status":"external_unreviewed",
    "curated_knowledge":false
  }]
}
```

此处为结构示例，不是真实高德结果。每条实际返回同时提供高德地点链接。外部结果不自动入库、不伪装成旅发局资料，也不补造营业时间或评价。对话中明确的“某地点在哪里/怎么去/请介绍某地点”及空检索会接到该补充流程；不是任意自然语言实体识别。地区、名称、别名和香港覆盖不足时会明确提示。地点页也提供独立查询入口和 JSON 展开。

## 高德路线图

`POST /api/amap/route`：`{"place_ids":["tai-kwun","pmq"]}`，支持 2–6 个不同本地地点。先在高德搜索并唯一确认地点，使用其返回的坐标计算步行路线；**不会把原本近似 WGS84 坐标当作高德坐标**。返回各段米数/秒数/路径、供应商来源与请求时间，静态地图成功时额外返回 PNG 数据。静态图失败时只渲染真实返回的路径并说明无底图；算路失败时保留 OpenStreetMap 行程地图，不将估算改称导航。

这是额外的步行参考，不替换行程中的公共交通估算；跨海、山区、香港数据覆盖及供应商权限可能导致失败。高德文档：[POI 搜索](https://lbs.amap.com/api/webservice/guide/api-advanced/search)、[静态地图](https://lbs.amap.com/api/webservice/guide/api/staticmaps)、[路线服务](https://lbs.amap.com/api/webservice/guide/api/direction)。

更新至 2026-10-22：本机已按用户要求启用 `AMAP_ENABLED=true`，COA 地点搜索及一段星光大道至诺士佛台步行路线／静态图已实际返回。该运行检查不代表全部香港覆盖或导航准确率。接口错误脱敏，密钥不返回浏览器。新增 `POST /api/walking-map` 接收 `origin_id`、`destination_id`，多候选时返回供用户选择的地点，再通过 `origin_poi_id`、`destination_poi_id` 选择；服务端重新查询验证所选 POI。局部地图使用高德原生图显示路线，OSM 街道图只标本地近似起终点。

## 测试与边界

新增检查覆盖持久历史跨 Agent/客户端恢复、同一会话改行程、规划后转回地点问答、侧栏条件、删除历史、容量与 ID、冷门地点未配置提示、本地命中不发地图请求、地图结果香港过滤与来源、错误/空结果区分、供应商坐标路线与静态图片、歧义时不猜坐标、两阶段重排及筛选。原资料数量与核对日期断言按明确新增的 12 条更新，保留其他质量约束。

首次测试发现旧断言固定为 21 条/10 月 19 日，以及检索错误提示语言不一致；已按新资料范围更新断言并保留中文错误提示。首次页面点击还发现事件代理把 `body[data-view]` 当成导航按钮，已限定为真实按钮/链接并复核首页规划跳转。未访问 Canvas、未改简历、未推送 GitHub，未公开部署。

真实模型对两个景点的比较首次返回了两个并行工具建议，即使请求中设置了 `parallel_tool_calls=false`。旧适配器拒绝该批次；现改为只执行首个、将实际结果反馈后再决策，未执行的建议不会伪造响应。同一轮连续搜索的规范来源合并保留，避免第二次搜索覆盖第一次证据；新增模拟回归覆盖串行执行和双来源引用。模型失败时也不再显示“引用已校验”的成功文案。

外部调试曾因可能发送本机历史被自动审批拒绝，该操作没有执行；定位兼容问题使用的是不读历史的手写公开景点问题。用户日常主动开启模型时发送有限上下文的行为与此调试操作不同，仍按页面说明运行。


## 2026-10-22 真实行程地图修复

原网格 SVG 改为本地 Leaflet 1.9.4 + OpenStreetMap 在线底图，无需高德 Key。显示行程编号，按日分色，支持全程/按日切换、缩放拖动、景点弹窗与详情、高德外链。只加载进入视野的地图，遵守浏览器缓存，不预取或打包地图瓦片；保留 OSM 署名和问题反馈链接。网络失败时明确提示，不用空白网格冒充底图。

坐标仍是本项目的人工近似 WGS84 定位；真实底图不代表标记已逐条精确校准，虚线仍是游览顺序。高德返回的 GCJ-02 路径不叠到 OSM，以免坐标系混用。真实算路仍由原高德接口单独提供。

`AMAP_ENABLED=false` 现在返回 `disabled`，与缺失 Key 的 `not_configured` 区分。小众地点接口在无结果时保留高德/OSM 搜索链接，返回空 results，不伪造地点 JSON。现有密钥及关闭设置不变。

安全策略只为图片增加 `https://tile.openstreetmap.org`；脚本与网络 API 仍仅允许同源。页面默认 `no-referrer` 不变，只有地图瓦片图片显式使用 `referrerPolicy: origin`，按服务要求发送本地来源，不发送问题、对话或密钥。Leaflet 固定版本及 BSD-2-Clause 许可证随源码保存。

参考：[Leaflet 文档](https://leafletjs.com/reference.html)、[OSM 瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)、[高德 URI 搜索](https://lbs.amap.com/api/uri-api/guide/search/search)。本地个人演示采用公共瓦片服务；公开规模化部署前需另选有容量保证的服务。


## 2026-10-22 地点统一搜索与真实高德查询

地点页合并为一个搜索框，旧的“小众地点”第二入口移除。输入停顿 650ms 后自动检索，也可按 Enter 或点击搜索。`POST /api/places/search` 先查本地相关资料，真正未命中时才调用高德。地区筛选排除已有本地结果时提示切换“全部”，不将筛选无命中谎报为资料库未收录。外部地点按高德区名筛选；未能确认地区的候选不会混入。

本次用户明确要求直接查询高德，本机 `.env` 已设为 `AMAP_ENABLED=true`，既有 Key 保持私密。COA/coa 已经通过真实服务端 API 和网页入口返回 2 条香港候选，含地址、分类、坐标及来源时间。搜索成功不代表路线、静态地图或其他高德服务已真实验证。

页面在同一区域显示“资料库中未找到”与高德补充结果，支持展开 JSON，外部地点仍标为未人工审核、不自动入库。错误、空结果、地区不匹配、关闭和未配置分别呈现，不用地图网站外链冒充已经取得的数据。成功取得地点时不再出现“尚未取得地点数据”的旧提示。

前端使用请求序号防止较慢的旧搜索覆盖新输入；相同正在进行的查询合并等待，成功／空结果保留 3 分钟内存缓存，最多 30 项；不写入浏览器持久存储或知识库。清空输入恢复本地目录，中文输入过程中不抢先请求。所有真实供应商调用仍由服务端使用 Key，不将 Key 发给浏览器。验收与回归见 `docs/evidence/unified-search/`。
