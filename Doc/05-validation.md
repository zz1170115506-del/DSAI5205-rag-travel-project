## 与原设计的具体落地差异

- 前端采用原生 ES Modules，不增加 Node 构建容器；原仓库没有现成前端源码。
- 开发预览可用 SQLite；部署目标仍是 MySQL。SQLite 结果不用于声称 MySQL 行为已验证。
- 访客身份使用随机不透明 Cookie 和数据库哈希，没有额外 SESSION_SIGNING_SECRET；跨设备登录不在首版。
- created_at/updated_at 在 MySQL 中用微秒精度；active_run_id/message.run_id 的循环关联由事务和归属检查维护，没有增加循环数据库外键。
- 数据格式和来源管理完整；原文入口目前是 UTF-8 文本/Markdown，PDF/OCR 需要预处理。
- 查询/筛选、关系、取消、记忆可独立使用；没有将业务模块拆成微服务。
- 语义质量仍需人工核查；当前没有自动 LLM 评委、实时交通服务、语音插话或任意 Token 原地恢复。

## 如何补做 MySQL 测试

创建一次性空测试库（名称必须以 `_test` 结尾），仅使用测试账号配置：

```bash
cd backend
TEST_DATABASE_URL='mysql+pymysql://测试账号:测试密码@127.0.0.1:3307/travel_test' python -m pytest -q
```

测试夹具会删除并重建该库中的本项目表，请勿使用业务数据库。Docker 默认不发布 MySQL 端口；可在专用本地测试 Compose override 中绑定 `127.0.0.1:3307:3306`，不要直接对公网发布。

完成 Docker 首次启动后，再按 Doc/03 的 DOCKER01—03 验收代理、恢复和数据卷；真实模型配置后使用真实数据集评测，不复用模拟质量结论。
