状态：计划，所有用例均未执行。六模块全部纳入最终交付，先后顺序用于降低集成风险。

全范围初估 26—41 人日，包含资料整理与基础集成，不含复杂实时交通或语音。属于规划估算，需 P0 后依据现有代码和人员经验修订；人日不能直接按人数整除为日历工期。评测样本从 P2 同步编写，取消控制接口从 P1 预留，避免最后补接。当前仅完成文档设计，不开始 P1。

建议职责：数据负责人管理来源/实体/关系；后端负责人管理数据库/检索/Agent；前端负责人管理卡片/地图/聊天/交互；集成负责人管理 Compose/测试/评测。人数较少时可一人兼任，不要求四名成员。

## 2. 每个模块的开发闭环

1. 先写可观察的需求和验收例子，确定依赖与测试数据。
2. 更新数据模型、迁移和 API 契约；新接口标记开发中。
3. 在功能分支实现最小完整流程，增加有意义的规则、边界和回归测试。
4. 单元和集成测试通过后做前端联调；模型适配器在常规自动测试中使用确定性替身。
5. 用独立的真实模型集成检查验证适配器；固定开发集评测，不使用保留测试集调参数。
6. PR 说明修改、验证、数据/配置变化和已知限制；审查后合并，更新运行说明。

已有 `feat/fullstack` 可继续承载集成工作；团队后续按实际协作需要拆分功能分支，保留已有修改。全部模块采用明确接口和开关，避免复制整条问答链。

## 3. 测试数据与执行层次

- 单元：字段校验、别名规范化、BM25 分词、RRF、关系过滤、距离、偏好优先级、状态迁移。
- 集成：真实临时 MySQL，验证外键、事务、归属校验、导入幂等、取消与完成竞争；不拿 SQLite 代替 MySQL 验证数据库语义。
- 前端：浏览器测试聊天、卡片地图联动、停止和纠正、记忆管理、断线恢复。
- 模型集成：小规模真实 API 检查向量维度、超时、流式关闭与调用错误；与离线测试分开运行。
- 离线评测：固定 JSONL、数据快照、配置和模型标识，保存逐条输出、引用、延迟与成本。
- 部署：Compose 启动、Nginx 流式代理、重启、迁移和备份恢复。

测试夹具使用少量虚构景点和 example.invalid 来源，明确标注 synthetic；事实评测使用核验过的香港景点，不混入虚构数据。

## 5. 评测设计与验收

检索消融：BM25、向量、BM25+向量、BM25+向量+关系。对话消融：固定混合检索下，基础单次 RAG 与受控 Agent。个性化对比：同一候选集合下记忆关闭/开启；纠正场景检查约束覆盖。每次只改变待研究因素，不能把更换模型的效果归因于图检索。

样本初步 100 条：事实 20、名称/多语言 10、条件检索 15、关系 15、比较/规划 10、多轮/纠正 10、无答案 10、个性化 10；错误注入和并发测试另设确定性夹具。按 group 分层约 70% 开发 / 30% 保留测试，尽量保持各类别覆盖；小样本报告样本数和类别结果，避免过度概括。

必过：数据外键完整、重复导入不重复、引用定位存在、取消旧任务不污染新结果、用户隔离、已删偏好不复用、幂等请求、容器重启持久化、版本错配阻止服务。确定性用例全部通过后才能交付。

性能初步目标：本地停止操作后 1 秒内 UI 停止追加，3 并发会话下无串流；记录取消 API 确认与上游停止耗时，不能混为同一指标。检索延迟目标待固定数据规模和机器后确定。TTFT 的计时起点为后端接收有效请求，终点为第一个答案 Token，状态事件不算 Token。上述目标需实测，不代表已经达成。

问答正确率、Recall@5 等先建立基线再确定验收阈值。增强项若未显著改善，保留实现和实验结果，说明适用问题类型，不能声称必然优于基线。
