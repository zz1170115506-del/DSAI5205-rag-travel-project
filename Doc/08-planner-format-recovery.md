# 查询计划格式错误与容错修复

日期：2026-10-24。

## 本次定位

最近失败任务错误码为 `ValidationError`，trace_entries=0，说明失败发生在查询计划完成前，尚未进入检索。部署容器正常、索引就绪检查成功。旧版只保存异常类型，没有记录字段级校验位置，因此不能断定原始输出具体哪个字段不合要求。

原提示“任务未完成，请检查模型配置、索引状态或稍后重试”将多类错误合并，容易误导为密钥或索引问题。

## 修复

- 严格校验模型给出的查询计划；非法意图、空/错误类型的查询、非法筛选值、过长查询等改用受控基础计划。
- 降级使用当前问题与已通过规则解析的条件，不执行模型生成的任意字段、SQL 或工具调用。
- null 筛选项不再覆盖已经明确解析的条件；较长问题拆分为有界检索查询。
- JSON响应结构异常使用专门错误类型；计划回退在诊断记录中有明确标识。
- 超时、鉴权、限流、网络、索引、维度等显示不同提示，并附短任务编号。
- 校验诊断只记录预定义字段名和错误类型，不记录原始响应或异常输入。

## 验证

本地合成回归：43项通过，其中新增12项针对格式兼容、保留条件、受控降级、完整任务成功和敏感内容不出现在错误消息中的检查。没有使用原始用户对话进行模型重放。

实际部署：更新后端镜像并通过就绪检查，重新启动Nginx以刷新后端地址。使用全新访客和预先编写的虚构问题进行真实模型检查；结果记录以本次工具执行为准，不等同于原始失败对话已被逐字复现。

用户可以自行点击“重新提问”发起新的请求；不自动重发用户历史消息。
